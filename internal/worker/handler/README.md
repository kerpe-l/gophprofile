# worker/handler

Обработчики событий: `avatar.uploaded` — создать миниатюры, `avatar.deleted` —
убрать файлы из хранилища.

- **Идемпотентность через статус в базе.** Перед работой статус перечитывается;
  событие уже обработанного или удалённого аватара подтверждается без действий —
  повторная доставка не порождает повторной записи в хранилище. Событие аватара
  в `processing` работу начинает заново: это повторная доставка после падения
  обработчика, и домен такой переход разрешает.
- **Классификация ошибок решает судьбу сообщения.** Обёрнутые
  в `broker.ErrNonRetryable` — битый файл, неподдерживаемый формат, пропавший
  оригинал — переводят запись в `failed`, сообщение подтверждается: повтор через
  пять минут битый JPEG не починит. Остальное — отказы базы и хранилища — уходит
  на лестницу повторов. `retry_count` в базе информационный; решение о DLQ
  принимается по счётчику в заголовках сообщения.
- **Оригинал вычитывается в память с пределом** (`maxOriginalBytes`): объект
  больше лимита загрузки в хранилище не клали, и разворачивать его незачем.

Фикстуры тестов описаны в [testdata/README.md](testdata/README.md).
